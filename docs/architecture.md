# Architecture

This document describes the codebase structure, module responsibilities, and data flow of the Priority Plus Navigation plugin.

## Project Structure

```
priority-plus-navigation/
+-- classes/                          # PHP backend
|   +-- class-block-renderer.php      # Filters block output, injects data attributes & styles
|   +-- class-css-converter.php       # Converts attribute values to CSS custom properties
|   +-- class-enqueues.php            # Manages script/style enqueueing
|   +-- class-plugin-module.php       # Abstract base class for modules
|   +-- class-plugin-paths.php        # Resolves file paths, URLs, and asset metadata
+-- src/                              # JavaScript/SCSS source
|   +-- config.js                     # Runtime config (labels, gaps, breakpoints, icons)
|   +-- tokens.js                     # Design tokens (default styling values)
|   +-- priority-plus-navigation.js   # Frontend entry point
|   +-- priority-plus-nav-editor.js   # Editor entry point
|   +-- core/
|   |   +-- PriorityNav.js            # Main class: overflow detection, dropdown, state
|   +-- dom/
|   |   +-- dom-builder.js            # Creates More button and dropdown HTML
|   |   +-- dom-extractor.js          # Extracts nav item data from DOM
|   +-- layout/
|   |   +-- width-calculator.js       # Calculates available space and visible item count
|   +-- events/
|   |   +-- accordion-handler.js      # Manages submenu accordion interactions
|   |   +-- event-handlers.js         # Manages all event listeners (click, keyboard, outside)
|   +-- utils/
|   |   +-- dom-utils.js              # DOM measurement and visibility helpers
|   |   +-- html-utils.js             # HTML escaping
|   +-- styles/
|   |   +-- _variables.scss           # CSS custom property defaults and shared mixin
|   |   +-- style.scss                # Frontend styles
|   |   +-- editor.scss               # Editor styles
|   +-- variation/
|       +-- block.js                  # Block variation registration and attribute definitions
|       +-- controls.js               # Inspector panel controls (higher-order component)
|       +-- components/
|           +-- more-button-preview.js          # Editor More button preview
|           +-- dropdown-customizer-modal.js    # Dropdown styling modal with live preview
|           +-- dropdown-preview.js             # Live dropdown preview inside the modal
|           +-- modal.scss                      # Modal-specific styles
|           +-- panels/
|               +-- menu-color-panel.js         # Menu color controls
|               +-- menu-items-panel.js         # Item padding, separator, indent controls
|               +-- menu-styles-panel.js        # Border, radius, shadow controls
|               +-- submenu-color-panel.js      # Submenu color controls
+-- build/                            # Compiled assets (generated by wp-scripts)
+-- docs/                             # Documentation
+-- assets/                           # Plugin icons and images
+-- priority-plus-navigation.php      # Main plugin file (entry point)
+-- package.json                      # Node dependencies and scripts
+-- webpack.config.js                 # Build configuration
+-- composer.json                     # PHP dependencies (autoloading)
```

## PHP Backend

### Entry Point

`priority-plus-navigation.php` bootstraps the plugin:

1. Loads the Composer autoloader
2. Creates shared dependencies (`Enqueues`, `CSS_Converter`)
3. Creates `Block_Renderer` with a callback reference to `Enqueues::enqueue_frontend_assets()`
4. Initializes all modules via their `init()` methods

### Module Pattern

All modules extend `Plugin_Module`, which provides an abstract `init()` method for registering WordPress hooks.

### Block_Renderer

The core PHP class. It:

1. Hooks into `render_block` filter
2. Checks if the block is `core/navigation` with Priority+ enabled
3. Collects all `priorityPlus*` attributes from the block
4. Injects data attributes (`data-more-label`, `data-more-icon`, `data-overlay-menu`, `data-mobile-collapse`)
5. Builds inline CSS custom properties from attribute values
6. Preserves any existing WordPress inline styles (typography, etc.)
7. Triggers frontend asset enqueueing via callback

### CSS_Converter

Stateless utility class that handles:

- **Preset values**: `var:preset|spacing|30` to `var(--wp--preset--spacing--30)`
- **Border conversion**: Flat and per-side formats to CSS custom properties
- **Border radius**: String or per-corner object to CSS shorthand
- **Padding**: Per-side object to CSS shorthand with preset support

### Enqueues

Manages asset registration:

- Editor assets enqueued on `enqueue_block_editor_assets` hook (always loaded)
- Frontend assets enqueued on-demand via callback from `Block_Renderer` (only when a Priority+ block is on the page)

## JavaScript Frontend

### Entry Point

`priority-plus-navigation.js` runs on `DOMContentLoaded`:

```javascript
document.querySelectorAll('.is-style-priority-plus-navigation')
  .forEach(nav => new PriorityNav(nav));
```

### PriorityNav Class

The main orchestrator (`src/core/PriorityNav.js`):

1. Reads data attributes from the `<nav>` element
2. Creates the More button and dropdown container via `dom-builder`
3. Sets up `ResizeObserver` for layout changes
4. Sets up `MutationObserver` for hamburger menu detection
5. Runs `checkOverflow()` to calculate and update visible items

### Module Responsibilities

| Module | Responsibility |
|--------|---------------|
| `core/PriorityNav.js` | State management, lifecycle, coordination |
| `dom/dom-builder.js` | Creates More button HTML, dropdown list, accordion markup |
| `dom/dom-extractor.js` | Extracts label, URL, submenu data from nav items |
| `layout/width-calculator.js` | Measures items, calculates how many fit |
| `events/event-handlers.js` | Click outside, Escape key, resize handlers |
| `events/accordion-handler.js` | Submenu open/close, ARIA updates |
| `utils/dom-utils.js` | `isMeasurable()`, `getComputedGap()`, visibility checks |
| `utils/html-utils.js` | `escapeHtml()` for safe string rendering |

## JavaScript Editor

### Entry Point

`priority-plus-nav-editor.js` imports:

1. `variation/block.js` — Registers the block variation and extends attributes
2. `variation/controls.js` — Adds inspector controls via `editor.BlockEdit` filter
3. Editor styles

### Block Variation (`block.js`)

Two operations:

1. **`registerBlockVariation`** — Registers `priority-plus-navigation` variation of `core/navigation` with default attributes and `isActive` check
2. **`addFilter('blocks.registerBlockType')`** — Extends `core/navigation` with 30+ `priorityPlus*` attributes using design tokens as defaults

### Controls (`controls.js`)

Two higher-order components applied via `editor.BlockEdit` filter:

1. **`addDisableAlwaysOption`** (priority 5) — Visually disables the "Always" overlay menu option when Priority+ is active
2. **`withPriorityPlusControls`** (priority 10) — Wraps the block edit with:
   - `MoreButtonPreview` component (fake More button in the editor)
   - Inspector panels for label, colors, padding, border, border radius
   - `DropdownCustomizerModal` for menu styling
   - Auto-conversion of `overlayMenu: 'always'` to `'mobile'`

### More Button Preview

`components/more-button-preview.js` renders a styled `<span>` in the editor that:

- Reads computed font styles from actual nav items via `getComputedStyle()`
- Reflects the toggle label, colors, padding, border, and border radius attributes
- Selects the navigation block when clicked (via `selectBlock(clientId)`)

## CSS Architecture

### Three Files

| File | Purpose |
|------|---------|
| `_variables.scss` | `:root` defaults + `@mixin dropdown-aliases` |
| `style.scss` | Frontend styles (loaded on page) |
| `editor.scss` | Editor styles (loaded in block editor) |

### Custom Property Layers

1. **`:root`** — Plugin defaults defined in `_variables.scss`
2. **`body`** — Theme.json overrides (WordPress auto-generates from `settings.custom`)
3. **`<nav style="...">`** — Block-level overrides from inspector controls (inline styles)

### Alias Pattern

Long WordPress custom property names are aliased to short `--ppn-dropdown-*` names via a shared SCSS mixin:

```scss
@mixin dropdown-aliases {
  --ppn-dropdown-bg: var(--wp--custom--priority-plus-navigation--dropdown--background-color);
  --ppn-dropdown-item-color: var(--wp--custom--priority-plus-navigation--dropdown--item-text-color, #191919);
  // ... 16 more aliases
}
```

Both `style.scss` and `editor.scss` include this mixin on the `.priority-plus-navigation-dropdown` selector, ensuring a single source of truth.

## Design Tokens

`src/tokens.js` defines default values structured by visual concern:

```javascript
export const tokens = {
  toggle: { border: {...}, borderRadius: ... },
  dropdown: {
    backgroundColor, border: {...}, borderRadius, boxShadow,
    item: { padding: {...}, hoverBackground, textColor, hoverTextColor, separator: {...} },
    submenu: { indent, backgroundColor, itemHoverBackground, itemTextColor, itemHoverTextColor }
  }
};
```

These tokens are used:
- As default values for block attributes in `block.js`
- As reset values in the inspector controls
- As fallback values in the dropdown customizer modal preview

## Runtime Config

`src/config.js` defines behavioral constants:

```javascript
export const config = {
  moreLabel: 'More',          // Default toggle button label
  gap: 8,                      // Default gap between items (px)
  mobileBreakpoint: 600,       // Mobile collapse breakpoint (px)
  chevronIconSvg: '...'        // SVG markup for the dropdown chevron
};
```

## Data Flow

### Frontend Render Pipeline

```
WordPress renders core/navigation HTML
    |
Block_Renderer::render_block() filter
    |
    +-- Check: Is Priority+ enabled? (attribute or class name)
    +-- Check: Is overlayMenu !== 'always'?
    +-- Collect all priorityPlus* attributes
    +-- Build inline CSS custom properties
    +-- Inject data-* attributes into <nav>
    +-- Enqueue frontend JS/CSS
    |
Browser loads page
    |
PriorityNav.js reads data-* attributes from <nav>
    |
    +-- Create More button + dropdown container
    +-- Measure item widths
    +-- Calculate visible count
    +-- Hide overflow items
    +-- Build dropdown with accordion support
    +-- Watch for resize/hamburger changes
```

### Editor Pipeline

```
Block editor loads core/navigation
    |
block.js registers variation + extends attributes
    |
controls.js wraps BlockEdit with HOC
    |
    +-- Render MoreButtonPreview (styled <span>)
    +-- Render inspector panels (label, colors, spacing, border)
    +-- Render dropdown customizer modal (on button click)
    |
User changes attributes via inspector
    |
    +-- Attributes saved to block
    +-- Block_Renderer reads them on frontend render
    +-- Converted to CSS custom properties
```
